## Per-run accounting

The CSV is the sole machine-readable status source for all 30 configurations. Each row separates standard 1000-step results from demonstration-only extensions and tracks legal t0 identity, search runs, candidate geometries and routes, native outcomes or failure reasons, code fingerprint, and archive path. This Markdown file documents scope and protocol only. A run counts as a success only when its continuous physical action record is complete and the active native `task_success` is true. A demonstration-only success never changes the standard-1000 result.

All primary runs use the existing V3 cold-start workflow from an identity-checked legal t0; they do not load target-scene successful trajectories or actions, change BDDL, or write physical state directly. The initial search order began with obstacle_avoidance L0T3 and L0T4; both have a recorded bounded failure. Coverage now advances through obstacle_avoidance L1/L2; after L1T4 dev02, the current item is L2T1. L1T3 dev01/dev02 are archived for later shared-candidate-family retesting, followed by obstacle_avoidance_human configurations. Revisit failed tasks after a meaningful public search change. Once coverage is accumulated, a fixed code fingerprint and one shared search budget will be frozen for cross-scene evaluation; development-tuned and untuned configurations will be reported separately.

Strict-10mm and authorized 2mm finger-contact limits remain unchanged for their safety assessments.
